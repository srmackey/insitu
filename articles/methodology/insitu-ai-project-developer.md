# Insitu AI project developer

When this sitting would add or change standing agent guidance (a constitution, a skill, a host instruction file), treat that change as an Insitu artifact question first.

Link this article on any map that maintains those files. That includes the admin map, which maintains its own guidance like any other chair.

**How to follow**

1. Pause before writing the new rule or skill. Ask whether it is already an article, a role, or a pack member.
2. Inspect. `list_articles` and `where_used`. Prefer reuse. If the home is a pack member, edit the pack in the pack-authoring chair, bump VERSION, then update the install. Do not patch the installed copy as the new source.
3. If it is new and this chair only, write it here. Do not invent a trip through the vault for consistency.
4. If another project would reuse it, it belongs in Insitu: a native vault article for this user's operating context, or a pack if another map would install it. Do not author the pack in this chair. Say so, and point at the pack-authoring chair.
5. One idea per article. A second idea is a second article, not a stuffing.
6. **This chair writes its own map.** Mutating map tools take a project key, and the only correct value is this folder's basename. If this folder has no map, that is a miss to raise, not a license to pick another key.

**What this is not**

Composition authority: which maps receive which pack members, and any change to another map. That is the admin class, `methodology/insitu-guru`. This article is the change in front of you, in this chair, on this map.
